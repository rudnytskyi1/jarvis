# Несколько голосов в комнате

Локальная Community-1 определяет интервалы разных голосов. Faster-whisper
распознаёт неперекрывающиеся реплики отдельно и возвращает слова с временными
метками, а ECAPA сравнивает чистые участки каждого
голоса с зарегистрированными профилями. Всё аудио обрабатывается на сервере;
оплата OpenAI за этот этап отсутствует. Телеметрия pyannote отключена.

Известный голос получает имя, неизвестный — `Speaker 1`, `Speaker 2` и т. д.
Эти номера действуют только внутри одной записи. Два голоса, ошибочно совпавших
с одним профилем, остаются неизвестными: права администратора им не передаются.
Камера не используется как доказательство того, кто произнёс команду.

В активном `config.openai.yaml` установлено `reject_mixed_speech: false`.
Обычные запросы не отклоняются только из-за нескольких голосов, наложения речи,
паузы внутри фразы или неточных временных меток Whisper. Сначала выбирается
первое распознанное обращение Rowan и его продолжение до другого чистого голоса.
При одном говорящем части команды через паузы объединяются. Если выделить
обращение не удалось, распознанный текст всё равно обрабатывается, но владелец
смешанной записи остаётся неизвестным: личная история случайного человека
не подставляется. Это также действует для предварительных субтитров.

Наложение речи сохраняется в диагностике, но больше не вызывает обязательного
«говорите по очереди». Community-1 не разделяет смесь на независимые аудиопотоки:
чужие слова всё ещё могут попасть в распознанный текст. В профили голоса такие
записи не сохраняются; во время регистрации действует строгая проверка.

При `reject_mixed_speech: true` (значение по умолчанию) действуют описанные ниже
строгие правила. В этом режиме запросом считается одна непрерывная реплика,
начинающаяся с Rowan (или настроенного варианта wake word). Реплики друзей
остаются в локальном журнале и сообщении `transcript.segments`, но не поступают
в LLM как команды. После смены говорящего или паузы более 0,7 секунды дальнейшая
речь не добавляется к выбранной реплике. Если говорящий единственный и реплика
непрерывная, допустим уже сработавший wake word клиента без его текста в Whisper.
При нескольких говорящих без однозначного обращения ассистент просит повторить.
Исключение для паузы: отдельное «Rowan» и следующая реплика того же человека
в течение трёх секунд объединяются, если никто другой между ними не говорил.
В режиме `wake_word`, если Whisper отбросил первый короткий фрагмент (не более
1,25 секунды) как шум, распознанная следующая реплика сохраняется при единственном
обнаруженном говорящем. Непустые слова, отрицания и пропуски последующих реплик
так не отбрасываются; при нескольких голосах это исключение не применяется.

Наложение голосов помечается отдельно. Community-1 не восстанавливает два
независимых аудиопотока из смеси: при обнаруженном наложении в записи команды
не выполняются, ассистент просит говорить по очереди. Регистрация голоса также
не принимает записи с несколькими говорящими. Это консервативное поведение;
диаризация и распознавание могут ошибаться, особенно на коротких репликах,
дальнем микрофоне, телевизоре и похожих голосах. Поворот к другу без паузы или
смены говорящего пока не распознаётся как завершение обращения.

## Установка на сервере 5090

Условия доступа принимает владелец аккаунта на странице
[Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1).
Нужен локальный вход Hugging Face либо `HF_TOKEN`; токен не помещается в YAML.

Из корня проекта, в окружении `jarvis`:

```powershell
python -m pip install -r server/requirements-diarization.txt -c server/constraints-cuda.txt
python scripts/setup_diarization.py --download --enable --config config.openai.yaml
```

Файл constraints фиксирует CUDA torch/torchaudio текущего ПК, а также существующие
ruamel.yaml/protobuf. На другом сервере сначала согласуйте ограничения с его
установленными версиями. Проверенная здесь версия pyannote.audio — 4.0.7.
Загрузка весов происходит только при `--download`; обычный запуск читает локальный
каталог. `--enable` меняет профиль только после успешного тестового инференса,
включает `server.diarization.enabled` и увеличивает `client.vad.pre_roll_ms` до
1500, чтобы запись содержала само обращение Rowan. Другие профили не меняются.

Перезапустите сервер и клиент с обновлённым профилем. На клиенте нужен обновлённый
код для отображения отдельных реплик в консоли; установка pyannote там не нужна.
Без обновлённого pre-roll смешанные записи чаще потребуют повторного обращения.
Если диаризация включена, но модель не загрузилась, сервер не запускает обычное
распознавание смешанной записи как запасной вариант. При ошибке или таймауте
запрос завершается без действий. `/health` сообщает `diarization: true` после загрузки.

Настройки и значения по умолчанию:

```yaml
server:
  diarization:
    enabled: false
    reject_mixed_speech: true
    model_path: models/speaker-diarization-community-1
    device: cuda
    timeout_s: 45
    min_identity_s: 1.5
```

`min_identity_s` — минимальная длина чистого голоса для сравнения с профилем.
Это не задержка ожидания. Обработка начинается только после активной записи,
а ожидание wake word остаётся локальным на клиенте без облачной сессии.

## Проверки

```powershell
python -m pytest tests/test_diarization.py tests/test_diarization_pipeline.py tests/test_stt_noise_filter.py -q
python tests/live_diarization_smoke.py
```

Вторая команда создаёт два голоса через существующий Silero, проверяет
последовательную и одновременную речь и пишет измерения в
`data/diarization-smoke.json`. Она не вызывает OpenAI и не управляет устройствами.
Синтетический тест проверяет соединение компонентов, но не заменяет проверку
на реальном микрофоне комнаты с несколькими людьми.

Проверка на этом ПК: последовательные голоса Silero `en_0`/`en_29` разделились,
команда о громкости выделена отдельно от разговора об ужине; наложение этих
голосов обнаружено и отклонено. Первая проба с `en_0`/`en_50` показала ограничение:
модель объединила два коротких синтетических голоса в один. Поэтому точность
на реальных голосах комнаты требует отдельной проверки; безошибочное
определение говорящего этим тестом не подтверждается.
