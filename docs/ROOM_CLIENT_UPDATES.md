# Обновление клиента на всех комнатных ПК

Правило владельца (2026-09-22): **если изменился код клиента, его надо
обновить и перезапустить на всех ПК**, а не только на своём. Комната, на
которой осталась старая сборка, продолжает вести себя по-старому — и выглядит
это как «оно не работает», хотя в репозитории уже исправлено.

Один запуск делает всё:

```powershell
pwsh -File scripts/update-room-pcs.ps1
pwsh -File scripts/update-room-pcs.ps1 -Only buro        # один ПК
pwsh -File scripts/update-room-pcs.ps1 -DryRun           # только проверить связь
```

## Что скрипт делает

1. Собирает один пакет из `client/` и `common/` (без `__pycache__` и без
   `client/room-tracker.runtime.yaml` — это состояние конкретной комнаты).
2. По каждому ПК из `deploy/room-pcs.json` проверяет связь по SSH.
3. Для `"kind": "copy"`: копирует архив, останавливает задачу клиента,
   распаковывает код поверх, запускает задачу обратно.
4. Для `"kind": "git"`: делает `git pull --ff-only` в его клоне и
   перезапускает задачу.
5. Печатает таблицу: ПК, результат, **SHA-256 `client/camera.py` на ПК против
   этого рабочего каталога**, состояние задачи и число процессов `python`.
   Не совпал хэш — значит ПК реально не обновился, и это видно.

`config.yaml`, `data/`, модели и голоса на ПК не трогаются: пакет несёт только
код.

## Живое окно камеры (2026-09-24)

Клиент умеет показывать **живое видео со своей камеры** на экране комнаты — с
рамкой на каждой находке детектора и именем над человеком, которого хаб узнал
(`client/live_view.py`, возможность `camera_preview`). Включается и выключается
с хаба: голосом или из Telegram («открой камеру на buro») либо кнопкой
веб-панели `GET /admin/preview?room=<имя>&on=1|0`. Окно закрывается само, когда
клиент теряет связь с хабом, и живёт только пока его держат включённым. Кадры
комнаты при этом никуда не отправляются: хаб передаёт лишь команду и имена
треков. Обновите клиент на всех ПК (`scripts/update-room-pcs.ps1`), иначе
комната со старой сборкой на такую команду честно ответит, что живой просмотр
она не умеет.

## Инвентарь ПК — `deploy/room-pcs.json`

| Поле | Значение |
|---|---|
| `name` | Имя, которым владелец называет ПК (`buro`, `AntonDorm`) |
| `kind` | `copy` — обновляем файлами; `git` — `git pull --ff-only` |
| `host`, `user` | Адрес и пользователь для SSH |
| `key` | Приватный ключ на этом хабе (в git не попадает: `deploy/` не входит в релиз) |
| `root` | Каталог клиента на ПК |
| `task` | Имя задачи планировщика, которая запускает клиента в сеансе рабочего стола |

## Известные особенности (проверено на живых ПК)

* **AntonDorm (`C:\Users\Anton\Desktop\jarvis`)** — копия проекта без `.git`,
  поэтому только файлами. Задача `JarvisRoomClient` запускает
  `scripts\run-client.ps1`; она обязана быть `Interactive`, иначе HUD не
  появится на экране, и запускать её надо с `-WindowStyle Hidden` — окно
  PowerShell на телевизоре не нужно, HUD клиент рисует своим окном, а лог
  ведёт в `data\logs`. `scripts\update-room-pcs.ps1` правит действие задачи
  на месте (`Set-ScheduledTask`) и печатает `WINDOW=hidden|fixed`.
* **buro / BROANXL (`C:\Users\user\Desktop\rowanai`)** — клон публичного
  релиза `rowanai`, но `git pull` из SSH-сессии падает: Git Credential Manager
  не может сохранить креды без интерактивного сеанса
  (`Unable to persist credentials with the 'wincredman' credential store`).
  Пока это так, ПК в инвентаре стоит как `copy`. Если владелец заведёт токен —
  ПК можно перевести на `git`.
* На этом ПК клиент работает **на CPU** (`device=cpu`, `yolo11n`): тяжёлый
  `yolo11x` там не поднимается, и сторож быстрого прохода автоматически
  выключается, потому что тяжёлый детектор и так лёгкий.
* Публичный релиз для клонов собирается отдельно:
  `python scripts/publish_client.py --push` (см. `docs/CLIENT_DISTRIBUTION.md`).
* **Громкость комнаты всегда на нуле.** На каждом комнатном ПК лежит
  `data\keep-room-muted.ps1` — маленький сторожок: раз в 5 с читает динамики
  через pycaw и возвращает `mute + 0.0`, если что-то (Windows после смены
  устройства, игра, браузер, собственный `громче` клиента) подняло уровень.
  Он не трогает ни клиента Rowan, ни его задачу. Постоянство: на `AntonDorm` и
  `buro` заведена задача планировщика `RowanKeepRoomsSilent` (`schtasks`,
  запуск при входе), на ПК хаба — ярлык в папке Startup
  (`RowanKeepRoomsSilent.cmd`, там регистрация задачи требует UAC). Лог —
  `data\room-mute.log` рядом со скриптом. Проверка: громкость поднимали до
  0.7 на всех трёх ПК — сторожок вернул ноль в течение 5–15 с. Пакет
  обновления (`scripts\update-room-pcs.ps1`) везёт `keep-room-muted.ps1` в
  `data\` вместе с клиентом, чтобы копия на комнате не устаревала: задача
  комнаты запускает именно `data\keep-room-muted.ps1`.
