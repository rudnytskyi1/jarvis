# Telegram: полный справочник настроек

Документ описывает **все** настройки Rowan, связанные с Telegram: что где
задаётся, что означает каждое поле в панели `/tools`, как работает доставка
уведомлений и какие значения допустимы. Интерфейс панели — на английском,
значения и ID остаются как их ввёл владелец.

Связанные документы: `docs/TELEGRAM.md` (бот и группа, English),
`docs/TELEGRAM_ADMIN.md` (разделы панели), `DECISIONS.md` (решения TG-01…TG-03).

## 1. Где живут настройки

| Что | Где | Кто меняет |
|---|---|---|
| Токен бота | `TELEGRAM_BOT_TOKEN` (файл `.env` на ПК-мозге, либо DPAPI-хранилище `%LOCALAPPDATA%\Jarvis\telegram-bot-token.dpapi`) | `set-telegram-key.bat` |
| Запуск и ID | `server.telegram.*` в `config.openai.yaml` | правка YAML + перезапуск |
| Доступ людей | тот же YAML (`control_user_id`, `admin_user_ids`) и панель → **Telegram users** | владелец |
| Правила уведомлений | панель → **Notifications**; хранятся в `data/telegram/alerts/alerts.sqlite3` | владелец, админ |
| Состояние доставок | там же, таблица `deliveries`; видно в **Status** («Notifications pending») | — |
| Список групп | `data/telegram/admin.sqlite3`, ключ `chats` (заполняется автоматически) | автоматически |

Секреты через панель сохранить нельзя: значения, похожие на токен/пароль или
ключ, отклоняются валидацией (`hub/telegram_admin_state.py`).

## 2. Настройки в config (`server.telegram`)

| Поле | Тип | Что делает |
|---|---|---|
| `enabled` | bool | Включает бота целиком. Выключено — ни сообщений, ни уведомлений. |
| `chat_id` | отрицательный int | «Основная» группа: в ней Rowan отвечает и по умолчанию туда шлёт уведомления с назначением `group`. Меняется только правкой YAML (в панели поле неизменяемое). |
| `control_user_id` | положительный int | **Владелец хаба**: панель `/tools` и в личке, и в основной группе, все права, личные уведомления. Его строку нельзя изменить или удалить. |
| `admin_user_ids` | список int | **Дополнительные админы**: те же права, что у владельца (панель, все возможности, личные уведомления). Состав определяет владелец через конфиг; панель не может ни выдать, ни отобрать это право. |
| `api_key_env` | строка | Имя переменной окружения с токеном. По умолчанию `TELEGRAM_BOT_TOKEN`. |
| `timeout_s` | 5…120 | Таймаут одного вызова Telegram API. |
| `poll_timeout_s` | 1…50 | Длинный опрос `getUpdates` (сколько секунд держать соединение). |
| `respond_to_mentions` | bool | Отвечать на `@bot` в основной группе. Выключено — бот молчит, пока к нему не обратятся в личке. |

Пример для этого хаба (`config.openai.yaml`, файл в git не попадает):

```yaml
  telegram:
    control_user_id: 8322835915
    admin_user_ids: [8928749210, 6617808228, 1328190425]
    enabled: true
    chat_id: -5442466420
    respond_to_mentions: true
    api_key_env: TELEGRAM_BOT_TOKEN
    timeout_s: 30
    poll_timeout_s: 25
```

## 3. Доступ людей

Роль назначается в панели → **Telegram users** (владелец видит всех, кого бот
встречал; непринятые заявки помечены как обычные участники).

| Роль | Чат | Изображения | Камера | ПК | Память | Профили | Панель `/tools` |
|---|---|---|---|---|---|---|---|
| owner (`control_user_id`) | да | да | да | да | да | да | да |
| admin из `admin_user_ids` | да | да | да | да | да | да | да |
| admin (роль в панели) | да | да | да | да | да | да | нет (только если не назван в конфиге) |
| operator | да | да | да | да | нет | нет | нет |
| member | да | да | нет | нет | нет | нет | нет |
| blocked | нет | нет | нет | нет | нет | нет | нет |

Что означают шесть прав:

- **chat** — обычный разговор с Rowan в группе и в личке.
- **images** — отправка картинок (бот принимает фото от такого аккаунта).
- **camera** — попросить свежий кадр с камеры комнаты.
- **pc** — действия на компьютере комнаты (приложения, окна, громкость и т.д.).
- **memory** — читать и менять общую память дома.
- **profiles** — менять профили людей (голос/лицо), переименование, сброс.

Кнопки панели живут 15 минут и одноразовы. Формы ждут ответ **на конкретное
сообщение-подсказку**; `/cancel` закрывает ввод.

## 4. Разделы панели

| Кнопка | Что внутри |
|---|---|
| **Status** | Компьютеры онлайн, модель, профили, бюджет, состояние службы уведомлений. |
| **Settings** | Настройки моделей, STT, голосов, лиц, TTS, изображений, записи. Часть применяется после перезапуска. |
| **Shared memory** / **Personal memory** | Общие факты дома и личные заметки (личное открывается в личке владельца). |
| **People profiles** | Профили людей: роли, эталоны голоса/лица, сброс, удаление. |
| **Telegram users** | Роли и права людей, добавление по числовому ID. |
| **Computers and cameras** | Подключённые и известные ПК, выбор места, живой снимок камеры. |
| **Notifications** | Правила уведомлений (см. раздел 5). |
| **Audit log** | Кто что менял; секреты не пишутся. |
| **Calibration**, **Wall switches**, **Scenes** | Калибровка переключателей, устройства, сцены. |
| **Homes and owners** | Дома и их владельцы: выдача дома конкретному Telegram-ID. |

## 5. Правило уведомления: каждое поле

Новое правило создаётся **выключенным**: включение — отдельное подтверждение,
потому что включённое правило само отправляет фото и видео.

| Поле в панели | Ключ | Значения и смысл |
|---|---|---|
| **Workplace and camera** | `workplace_id` | Какое место (ПК) слушать. `Any workplace` — все. Показываются **только подключённые сейчас** ПК; ранее выбранный показывается как `Offline · <имя>`, чтобы правило не «ждало» выключенный компьютер. |
| **What to watch** | `event` | Событие: `Someone in frame` (человек стабильно в кадре), `Person came in`, `Person left`, `Unknown face appeared`, `Zone changed`, `Sound event`, `Object of interest`. |
| **Who to detect** | `target` | `Any person` / `Unknown face` / `Specific person`. |
| **Profile name** | `name` | Имя человека для `Specific person`; для `Object of interest` — метка объекта («посылка», «кот»). В остальных случаях не хранится. |
| **Zone** | `zone` | Имя зоны для `Zone changed`; пусто — любая зона. |
| **Attachment** | `media` | `Photo` или `Video` (клип `clip_seconds` секунд). Для канала HUD медиа не запрашивается. |
| **Destination** | `destination` | Куда слать: `Private chat (everyone) · N`, `Notifications group chat` (группа из `chat_id`) или группа по названию (например `RowanAI Notifications`). Подробно — в разделе 6. |
| **Delivery channel** | `channel` | `Telegram` / `Phone push` / `HUD caption`. Подробно — в разделе 7. |
| **Home** | `home_id` | Дом (комната), к событиям которого привязано правило; `Every home` — все. Дом владеет людьми, памятью и правилами, рабочее место — компьютер внутри дома. Список берётся из `homes:` в конфиге и из домов подключённых ПК, а не из базы: в базе остались тестовые дома прогонов. Пустое значение безопасно; названный дом, которому не принадлежит ни одно событие, правило не сработает. |
| **Notification cooldown, seconds** | `cooldown_s` | Пауза между двумя уведомлениями этого правила. Допустимо 1…86400 (по умолчанию 300). Пресеты: 1, 5, 15, 30, 60, 300. |
| **Stable presence, seconds** | `min_stable_s` | Сколько человек должен быть в кадре, прежде чем правило сработает. 0…300 (по умолчанию 2). Пресеты: 0, 0.5, 1, 2, 5, 10. |
| **Absence before a new entry, seconds** | `absence_s` | Сколько человек должен отсутствовать, чтобы следующий приход снова считался «пришёл». 0…3600 (по умолчанию 15). |
| **Video duration, seconds** | `clip_seconds` | Длина клипа для `Attachment: Video`. Пресеты: 3, 5, 8, 10. |
| **Quiet hours start/end** | `quiet_start`, `quiet_end` | Тихие часы правила в формате `HH:MM`; `-` или пусто — выключено. Начало и конец задаются парой. |
| **IANA time zone** | `timezone` | Часовой пояс для тихих часов правила, например `America/Chicago`. |

Отдельно у **дома** есть свои тихие часы и минимальный кулдаун
(`homes[].quiet_hours`, `homes[].alert_cooldown_s` в конфиге): тихие часы дома
действуют на все его правила, а дом может только **увеличить** паузу, не
уменьшить. Если правило и дом задают кулдаун, берётся больший.

## 6. Назначение (Destination): кому уходит уведомление

| Пункт | Что реально происходит |
|---|---|
| **Private chat (everyone) · N** | Личное сообщение **каждому, у кого есть доступ**: владельцу, названным в `admin_user_ids` и всем аккаунтам с выданным правом `chat`. Число N — сколько получателей сейчас. |
| **Notifications group chat** | Группа из `chat_id` в конфиге (совместимость со старой схемой). |
| **<Название группы>**, например `RowanAI Notifications` | Конкретная группа, которую бот знает; хранится как `group:<chat_id>`. |

Как группа попадает в список: бот **не может** спросить у Telegram свои группы,
поэтому хаб запоминает каждую, где он получил хоть один апдейт (сообщение,
добавление в группу, правка, нажатие кнопки) — до 20 групп, с отметкой времени.
Новая группа появляется в опциях сама после первого события в ней.

Важно: Telegram запрещает боту писать первым. Чтобы личные уведомления доходили,
человек должен хотя бы раз сам написать боту (нажать `/start`). Частичная
доставка помечается как `uncertain` и **не повторяется** — так не бывает дублей.

## 7. Канал доставки (Delivery channel)

| Канал | Как работает |
|---|---|
| **Telegram** | Сообщение (фото/клип с подписью) в выбранное назначение. Единственный канал, который работает «наружу». |
| **HUD caption** | Подпись на экране комнаты: клиент показывает текст (`MSG_STATUS`), медиа не запрашивается. Если комната занята (говорит/слушает) или офлайн, доставка отменяется без повторов. |
| **Phone push** | Заготовка ТЗ F-712: транспорт пуша появляется в фазе 3. Пока транспорта нет, правило честно помечается `skipped` с причиной «Push transport is not configured yet» — и ничего не отправляет. |

## 8. Служебные команды и маршруты

- `/tools` — открыть панель (владелец, названные админы, владелец дома в своём чате).
- `/tools@BotName` — та же команда в группе; `/tools@OtherBot` игнорируется.
- `/cancel` — закрыть текущий ввод или черновик правила.
- Личка владельца дома показывает только его дома; админ хаба видит всё.
- Сообщения, отправленные боту **до** его запуска/перезапуска, намеренно
  пропускаются — после перезапуска напиши боту заново.

## 9. Диагностика

- `GET /health` → `telegram`, `telegram_error`, `telegram_control_user_id`,
  `telegram_mentions` — состояние бота.
- Панель → **Status**: «Notifications pending» и список доставок.
- `data/telegram/alerts/alerts.sqlite3` → таблица `deliveries`: статусы
  `sent` (доставлено), `uncertain` (подтверждения нет, повторов не будет),
  `skipped` (тихие часы, нет транспорта), `failed` (ошибка).
- Логи хаба: `data/server.log` (ошибки Telegram пишутся типом исключения,
  без токенов).
