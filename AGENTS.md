# Rowan — инструкции для исполнителя

Rowan — распределённый голосовой ассистент для общежитий: один хаб на
RTX 5090 обслуживает несколько комнат, в каждой стоит клиент-ПК.
ТЗ: `Rowan — ТЗ для реализации (распределённый голосовой ассистент для общежитий).pdf`
(извлечённый текст — `.tz_raw.txt`; план фаз — раздел 16, открытые вопросы —
раздел 17, критерии латентности — раздел 15.1, схема БД — раздел 14).

Ниже — режим работы. Он обязателен и имеет приоритет над привычкой
переспрашивать.

## Режим цикла

1. **Задачи берутся из `PROGRESS.md` строго по порядку.** Для каждой задачи:
   выполнить → `make test` → отметить задачу `[x]` в `PROGRESS.md` →
   взять следующую. Пока задача не закрыта, следующая не начинается.
   `git add` / `git commit` не выполнять: `.git` в песочнице только для чтения,
   коммиты делает внешний скрипт после каждого запуска. Отсутствие коммита
   не считается падением задачи. Если задача уже реализована в рабочем
   дереве, но не отмечена — прогнать тесты и отметить, не переделывать.
2. **Не отчитываться и не ждать ответа, вопросов не задавать.** При
   неоднозначности берётся вариант «по умолчанию» из раздела 17 ТЗ, выбор
   записывается в `DECISIONS.md` (формат: ID задачи, вопрос, выбранный
   вариант, обоснование, ссылка на пункт ТЗ). Если ответ заказчика придёт
   позже — решение пересматривается отдельной задачей.
3. **Правило «дождись подтверждения плана» (раздел 1 ТЗ, пункт 2)
   отключено.** План фазы пишется в `PLAN.md` (файлы создать/изменить,
   Pydantic-модели, таблицы, сообщения протокола, риски) и сразу
   выполняется. Ждать подтверждения не нужно.
4. **Суб-агентов и воркеров не запускать.** Вся работа — в одном цикле, в
   этом рабочем каталоге.
5. **Никогда не писать «выполнено», если команда реально не запускалась.**
   Статус `[x]` в `PROGRESS.md` и запись в `docs/TZ_STATUS.md` ставятся
   только после реально прогнанной проверки; что именно запускалось и с
   каким результатом — указывается рядом.
6. **Когда все задачи фазы закрыты** — разбить следующую фазу из раздела 16
   ТЗ на задачи в `PROGRESS.md` (20–40 задач по 10–30 минут, с ID функций
   вида `F-123`, `D-01`, `4.5`) и продолжать работу.
   Файл `DONE` создаётся только после фазы 5.
7. **Если одна задача падает 3 раза подряд** — создать `BLOCKED.md`
   (задача, ID, что именно запускалось, полный текст ошибки, что уже
   проверено) и остановиться.


Точная копия в `Makefile`: `make test`, `make hub`, `make client`,
`make migrate`, `make skill name=<name>`, `make test-regress`.

## Правила кода (из раздела 1 ТЗ)

- Не ломать работающее: каждая фаза заканчивается запускаемой системой.
  Протокол v1 поддерживается до конца фазы 2; новые возможности включаются
  флагом в конфиге, а не заменой старого поведения.
- Строгие типы везде: Pydantic v2, `extra="forbid"`; никакого разбора
  «сырых» dict в бизнес-логике.
- Никаких фейков: заглушка, притворяющаяся результатом, запрещена —
  `NotImplementedError` плюс запись в `docs/TZ_STATUS.md` и раздел 17 ТЗ.
- Один asyncio-цикл; блокирующие вызовы — в отдельных потоках; GPU-инференс —
  только через очередь из раздела 4.5 (`hub/gpu_queue.py`).
- Тесты обязательны на каждый новый модуль и на регрессии пайплайна.
- Языки: код, идентификаторы и коммиты — английский; строки для пользователя —
  язык пользователя (en/ru/es); документация — русский.
- Секреты — только в переменных окружения; никогда в git и в логах.

## Файлы состояния

| Файл | Назначение |
|---|---|
| `PROGRESS.md` | Задачи текущей фазы, чекбоксы, ID функций ТЗ |
| `PLAN.md` | План фазы: файлы, модели, таблицы, риски |
| `DECISIONS.md` | Выборы «по умолчанию» там, где ТЗ допускает варианты |
| `BLOCKED.md` | Появляется, только если задача падает 3 раза подряд |
| `DONE` | Появляется только после закрытия фазы 5 |
| `docs/TZ_STATUS.md` | Честный статус по пунктам ТЗ (обновляется после каждого блока работ) |

## Структура репозитория

| Каталог | Назначение |
|---|---|
| `hub/` | «Мозг»: WebSocket-сервер, речь, идентичность, память, Telegram, очередь GPU |
| `client/` | Клиент комнаты: микрофон, камера, HUD, действия на ПК и устройствах |
| `common/` | Общий контракт: протокол (v1 + v2), конфиги, модели тарифов |
| `migrations/` | Нумерованные миграции SQLite (`NNNN_name.py`) |
| `skills/` | Скиллы: `manifest.yaml` + модуль с `run(ctx, args) -> SkillResult` |
| `tests/` | pytest, включая регрессионный набор реплик (`tests/regress`) |
| `data/` | Локальные данные: `hub.db`, память, диалоги, медиа (в git не попадает) |

## Проверка перед закрытием задачи

1. `python -c "import hub.app"` — после любой правки `hub/app.py`.
2. `make test` — целиком, а не только изменённый файл тестов.
